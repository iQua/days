All protocol instantiations share the same acceptance semantics
(canonicalize-and-replay) and reuse the same obligation families
(ParamFreeze, MonotoneTime, PendingMatch, Gate, Accounting, SnapshotEq).
What differs is the **event vocabulary**, the **checker replay state**, the
**canonical key** — legacy families use `(time_ns, event_id)`; exact and
P10c families use the full `EventKey`
`(time_ns, phase, origin_node, origin_sequence)`, and some P10c checkers
require already-strict canonical order — and which obligations matter most.

See also:

- [/docs/reference/traces/schema](/docs/reference/traces/schema)
- [/docs/research/design](/docs/research/design)

## The checker inventory

The Lean build (`lean/lakefile.lean`) currently carries:

- **Legacy-engine families** (float protocols, `(time_ns, event_id)` key):
  DCQCN, PFC, CUBIC, DRR, WFQ, AQM/ECN.
- **Exact-engine families** (full `EventKey`): exact TCP and Static
  Priority.
- **P10c families** (exact engine, protocol-parity program): mechanisms,
  AQM, DCQCN, and collectives, plus the AQM/DCQCN cross-check that ties
  the two vocabularies together.

Backend capability boundaries apply to generation, not checking: PFC,
DCQCN, RED, and collective generators run on Scalar/CPU and are rejected by
the Metal/CUDA validator before execution, so those certificate families
are produced by CPU-side runs only.

## Summary table (legacy families)

| Protocol family | Trace file / event kinds (representative) | Checker replay state (high level) | Core obligations enforced |
|---|---|---|---|
| AQM / ECN marking | `aqm_events.csv`: `decision` | per-queue frozen params; per-queue accounting | ParamFreeze, SnapshotEq (decision legality), Accounting |
| PFC | `pfc_events.csv`: `pfc_sent`, `pfc_recv`, refresh | per-port/per-priority pause state + pending-map | PendingMatch, Gate (refresh/cooldown), ParamFreeze, hysteresis |
| WFQ scheduler | `wfq_events.csv`: `enqueue`, `schedule`, `depart` | queued packets + virtual time + pending scheduled packet | Accounting, PendingMatch, SnapshotEq (tags/time), choice rule (min finish tag) |
| DRR scheduler | `drr_events.csv`: `enqueue`, `schedule` | per-class FIFO queues + deficit counters + RR pointer | Accounting, SnapshotEq (deficit/pointer), choice rule (deficit eligibility), ParamFreeze |
| CUBIC microbench | `cubic_events.csv`: CC micro-events | per-endpoint CC state + frozen parameters | SnapshotEq, ParamFreeze, MonotoneTime |
| DCQCN | `dcqcn_events.csv`: `cnp_sent`, `cnp_recv`, `timer_tick` | per-endpoint gate/rate state + pending CNP map | PendingMatch, Gate, ParamFreeze, bounds — see [the DCQCN page](/docs/research/dcqcn-certificates) |

## Notes by instantiation

### AQM / ECN marking (`aqm_events.csv`)

One row per marking/drop decision at a queue: queue identity, packet
identity, occupancy context, policy parameters, chosen action. Checks:
parameters stable per queue (freeze-on-first-use); the logged action legal
under the policy and context; any probabilistic witness validated. The
exact engine's ECN-threshold marking has its own P10c certificate schema
under the full `EventKey`.

### PFC (`pfc_events.csv`)

PFC frames at emission and reception, with refresh/cooldown rows. Checks:
each `pfc_recv` matches a distinct earlier `pfc_sent`; refresh/cooldown
gates respected; per-port parameters constant. Legacy engine only as a
generator; the exact engine rejects PFC on device backends by validation.

### WFQ scheduler (`wfq_events.csv`)

Correctness hinges on small local state and a choice rule. Checks:
`schedule` chooses a packet with minimal finish tag; tags and virtual-time
witnesses match the deterministic reference; scheduled packets depart
exactly once. The exact engine computes WFQ in exact rational arithmetic,
and its P10c mechanism certificates check the same discipline under strict
`EventKey` order.

### DRR scheduler (`drr_events.csv`)

Deficit counters plus a round-robin pointer. Checks: scheduled packets
satisfy deficit eligibility at service time; deficit/pointer updates match
the reference rule; queue contents conserved under enqueue/schedule.

### CUBIC microbench (`cubic_events.csv`)

Demonstrates the design generalizes to end-host congestion-control update
rules: per-endpoint parameters frozen and consistent; the logged post-state
snapshot matches the replayed update rule; time monotone per endpoint under
canonical order. The exact engine's TCP (Reno and CUBIC in fixed-point
integer arithmetic) is covered by the exact TCP certificate family under
the full `EventKey`.
