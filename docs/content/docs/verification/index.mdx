---
title: Conformance Verification (LeanGuard)
description: Trace-certificate checking and executable Lean models for both Days engines.
---

Days ships a Lean 4 verification tree under `lean/`. It has two related surfaces:

- **Legacy protocol certificates**: `days-legacy`, built with the `lean` Cargo feature, writes
  `*_events.csv` files. LeanGuard canonicalizes and replays those traces.
- **Exact executor certificates and proofs**: the current executor exposes exact-integer transition
  records for TCP, AQM, DCQCN, PFC, schedulers, rate sources, and collectives. The P10c checkers
  replay their CSV projections using the executor's complete `EventKey`, while `lean/DaysExecutor/`
  formalizes the image, transition, safe-horizon, and round-execution model.

An accepted certificate means every recorded transition satisfies that checker's executable
reference semantics. It does not, by itself, prove code that was not represented in the trace.

This section covers:

- [Use guide](/docs/verification/leanguard): emit legacy traces, build the Lean targets, and run
  legacy or exact-executor checkers.
- [Design sketch](/docs/verification/design): canonical keys, replay contracts, and the separate
  `DaysExecutor` theorem surface.
