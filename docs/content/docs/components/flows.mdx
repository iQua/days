Days has two flow implementations. The legacy CLI builds Nexosim source and sink actors. The exact compiler lowers supported TOML into backend-neutral flow descriptors and source-owned generator state.

## Legacy actor path

Each `Flow` records its endpoints, type, traffic, route selection, priority, and dependency IDs. `Topology::attach_flows` creates one `PacketSource` and one `PacketSink` actor for every concrete flow.

The source and sink implementations depend on `flow_type`:

| Flow type | Source behavior | Sink behavior |
| --- | --- | --- |
| `PacketDistribution` | Samples arrival and packet-size distributions. | Counts delivery and owns last-packet completion. |
| `TCP` | Owns congestion control, retransmission, ACK handling, and completion. | Builds ACKs and cumulative receive state. |
| `DCQCN` | Owns pacing and reaction-point state. Requires the `dcqcn` feature. | Detects CE, rate-limits CNPs, and owns last-packet delivery state. |

`starts_before` and `starts_after` become `FlowFinishMsg` connections. Distribution sinks signal completion; TCP and DCQCN sources signal completion after their feedback-driven work finishes.

### Legacy routing

`Flow::compute_path` produces a path containing the source actor, switch IDs, and sink actor. `Topology::route_flows` installs two per-flow tables in each switch:

- `fib` routes data toward the sink.
- `r_fib` routes TCP ACKs and control packets toward the source.

Legacy supports per-flow `ShortestPath`, `ECMP`, and `PathFromConfig`. Root `routing.policy = "FatTreeEcmp"` uses the shared canonical fat-tree policy. Flow sets can choose `Random`, `SwitchOffsetHalf`, or `SameSwitchNext` endpoint pairing.

## Exact image path

Exact lowering creates a `FlowDescriptor` with stable `FlowId`, source and target `NodeId` values, priority, a directed data route, and a reverse feedback route. Routes contain `LinkId` values, not actor IDs.

The source host LP owns a `FlowGeneratorState`. The TOML compiler lowers supported traffic into these generator families:

- constant open-loop traffic for `PacketDistribution`
- source-owned TCP Reno or CUBIC state
- exact rate and controller state for DCQCN
- resolved stages for RingAllReduce and AllGather

Target hosts own TCP cumulative-ACK state and DCQCN notification-point state. Generator status records whether the next emission is scheduled, blocked, finished, or stopped beyond the scenario endpoint.

Exact lowering derives flow IDs and routes from canonical semantic keys. It rejects explicit flow IDs, dependency lists, per-flow routing, and explicit paths instead of discarding them. It also rejects nondeterministic packet distributions and transport options outside the exact mechanism set. See [Flow configuration](/docs/configuration/flows) for the accepted subsets.

Scalar and CPU execute every lowered generator family. Metal and CUDA execute supported constant, rate, and TCP generators, but capability validation rejects DCQCN and collective state before execution:

```text
backend Cuda does not support DCQCN controller or CNP state planes; use Scalar or Cpu
backend Metal does not support collective generators; use Scalar or Cpu
```
