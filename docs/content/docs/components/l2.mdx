Days implements Priority-based Flow Control in both runtime models. The state layout and control path differ.

## Legacy PFC actors

Legacy PFC requires the `l2_pfc` Cargo feature and `link.mode = "Pfc"`. The topology inserts three actors on each directed fabric edge:

```text
Scheduler
  -> PfcEgressGate
  -> Link
  -> PfcIngressPort
  -> downstream PacketSwitch
```

The gate and ingress exchange `PfcFrame` values; data uses `LinkFrame::Data(Packet)`. The `Link` type can serialize either `LinkFrame` variant at the configured bit rate. The installed topology sends forward data through that actor, while the ingress sends pause and resume frames directly to the upstream gate through `pfc_output`.

`PfcIngressPort` owns eight byte queues and tracks occupancy per 802.1Q priority. It asserts XOFF at or above `xoff`, clears it at or below `xon`, enforces optional ingress capacities, and can refresh pause frames or retry a blocked drain. Its `can_forward` closure reads the downstream scheduler's shared `QueueState` to avoid forwarding into a full queue.

`PfcEgressGate` owns per-priority queues and `paused_until` deadlines derived from pause quanta. It starts service only for an unpaused priority.

Legacy rejects configured propagation delay with PFC because this actor pipeline does not combine the two mechanisms.

## Exact PFC state

Exact lowering stores PFC state inside each switch-egress LP:

- `PfcIngressState` tracks byte occupancy, XON/XOFF thresholds, capacity, and asserted state for one monitored incoming link.
- `PfcQueueState::paused_by_controller` records every downstream controller that currently pauses each priority.

Admission increases monitored occupancy. Service selection decreases it. Crossing XOFF emits a 64-byte `PacketKind::Pfc` pause on the exact reverse-link channel; crossing XON emits a resume. The control packet arrives as an ordinary `RemoteArrival`, and the egress queue remains paused until every asserting controller resumes it.

The exact mechanism is edge-triggered. Nonzero refresh and drain timers are rejected during lowering. A zero XOFF or pause-quanta entry disables that priority. Exact PFC can coexist with lowered propagation delay because the reverse control channel carries the exact 64-byte serialization and propagation delay.

Scalar and CPU execute exact PFC. Metal and CUDA reject its state planes before allocating device work:

```text
backend Cuda does not support PFC per-priority link pause; use Scalar or Cpu
```

See [L2 and PFC configuration](/docs/configuration/l2) for thresholds and validation rules.
