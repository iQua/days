description: Message passing in Nexosim (Output<T>, Mailbox<M>, event sinks).

Nexosim models communicate via typed message passing:

- `Mailbox<M>`: the inbound queue for a model instance
- `Output<T>`: a typed, connectable output port
- `event_slot(...)` / `event_queue(...)`: bench sinks that return writer/reader handle pairs for observing outputs

Source: `crates/nexosim/src/ports.rs`

## Connecting models

During bench assembly, an `Output<T>` is connected to a handler method on another model:

```rust
producer.output.connect(Consumer::handle, &consumer_mailbox);
```

When the producer sends:

```rust
producer.output.send(msg).await;
```

Nexosim delivers the message to connected consumers at the current simulation time. Delayed delivery is achieved by scheduling future events via the simulation scheduler APIs.

## How Days uses this

Days builds a graph of models where, for example:

- `PacketSwitch.outputs[next_id]` connects to either
  - a scheduler’s `packet_received`, or
  - a sink/source endpoint handler
- schedulers connect their `output` to downstream switches (optionally through an L2 pipeline)

The important architectural property is that **models own their state** and only communicate through these ports, which makes it feasible to run many models concurrently.
