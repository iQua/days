Days is a discrete-event network simulator written in Rust. The repository
ships **two engines** that share a lineage but make different guarantees:

- **Days AGO (Adaptive Guaranteed Ordering), the exact engine.** A scenario
  is compiled into a
  `SimulationImage` — logical-process (LP) state plus canonical events — and
  executed on any of four backends: a serial **Scalar** reference, a
  multicore **CPU** pool, **Apple Metal**, or **NVIDIA CUDA**. Execution is
  *exact*: simultaneous events have one canonical order, no float appears in
  the semantics, and every backend reproduces the byte-identical complete
  state of the serial reference. Protocols are written once, as sequential
  per-entity state machines; the scalar and CPU backends execute that one
  compiled implementation, and the Metal and CUDA transition planes are
  ports of it, held byte-identical by the conformance matrix.
- **Legacy Days, the process-based engine.** The original actor
  implementation on Nexosim: each network element is a coroutine with
  private state, communicating by message passing, on a single- or
  multi-threaded runtime. It remains fully supported for CPU-only
  simulation and is the reference point the exact engine is measured
  against.

## What the exact engine guarantees

- **Byte-identity across backends.** The shipped corpus gate compares the
  CPU pool and every compiled device backend against the global Scalar
  reference: with device-omitted diagnostics excluded, the remaining
  complete result must be byte-for-byte identical, on every fixture in the
  corpus.
- **Scale with refuse-or-run capacity.** The device planner derives every
  arena capacity from the image before execution; a plan either fits or the
  attempt aborts with a typed fault — nothing is dropped silently. Compact
  readback returns only live regions, and an opt-in warm start reuses a
  prior run's converged sizing (sizing only; it cannot change an answer).
  The largest committed fixture runs 262,144 closed-loop TCP flows;
  campaign evidence records its complete state byte-identical across the
  two CUDA architectures the project measures on.
- **Capability honesty.** Metal and CUDA accept all five exact schedulers,
  TailDrop and ECN-threshold marking, and TCP Reno/CUBIC; they reject RED,
  PFC, DCQCN/CNP, and collective generators *before* execution with a
  precise, tested error. Unsupported never means silently different.

## What both engines offer

- **Config-driven experiments**: one TOML file describes topology, traffic,
  switch discipline, and logging.
- **Pluggable queueing/scheduling**: FIFO, DRR, WRR, WFQ, Static Priority
  (plus Virtual Clock in the legacy engine).
- **Transport and congestion control**: packet-distribution sources, TCP
  Reno/CUBIC (legacy additionally BBR), optional DCQCN, and feature-gated
  PFC in the legacy engine.
- **Structured outputs with `csv_logging`**: CSV reports default on; setting
  `csv_logging = false` performs no CSV, trace, or manifest filesystem work
  while preserving every correctness reduction — the configuration of choice
  for benchmarking.

## Quick start

Legacy engine, from the repo root:

```bash
RUST_LOG=info cargo run --release -p days-legacy --bin days -- configs/simple.toml
```

For the exact engine's build, fixtures, and backend selection, start at
[/docs/quickstart](/docs/quickstart); the CLI reference covers the
production runners.
