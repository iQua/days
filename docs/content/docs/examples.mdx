Run commands from the repository root.

## Legacy CLI and Rust example

```bash
RUST_LOG=info cargo run -p days-legacy --bin days -- configs/simple.toml
cargo run -p days-legacy --example basic
```

Other legacy examples are `ecn`, `switch`, `tcp`, `tcp_test`, and `wire`.

## Exact Scalar and CPU

Use the small T24 TCP smoke fixture:

```bash
cargo run --example scalar_benchmark -- \
  configs/benchmarks/tcp/fattree_k4_tcp_cubic_f16_smoke.toml

cargo run --example round_benchmark -- \
  configs/benchmarks/tcp/fattree_k4_tcp_cubic_f16_smoke.toml \
  --workers 2 --repetitions 1
```

The full T24 fixture list and expected shapes are pinned in
`configs/benchmarks/tcp/t24-corpus-manifest.md`.

## E5 wide TCP fixtures

E5 is a committed 8,192-flow, byte-terminated TCP family:

- `configs/benchmarks/p12/e5_wide_k32_q200.toml` (Reno primary)
- `configs/benchmarks/p12/e5_wide_k32_q200_cubic.toml`
- `configs/benchmarks/p12/e5_wide_k32_q256.toml` (backup)

For example, run the primary fixture on the exact CPU executor:

```bash
cargo run --release --example round_benchmark -- \
  configs/benchmarks/p12/e5_wide_k32_q200.toml \
  --workers 4 --repetitions 1
```

E6 is not in the post-cleanup tree used for this documentation refresh, so it
is not presented as runnable.

## Frontier fingerprint and capacity warm start

The P11 frontier fixture contains 262,144 TCP flows. A Scalar run is:

```bash
cargo run --release --bin t20f_frontier -- \
  configs/benchmarks/p11/rq9_frontier_closed_k32.toml \
  --engine scalar
```

For device execution, enable Metal or CUDA and use `--engine device`.
Capacity warm starts are opt-in sizing hints:

```bash
cargo run --release --features metal-spike --bin t20f_frontier -- \
  configs/benchmarks/tcp/fattree_k4_tcp_cubic_f16_smoke.toml \
  --engine device \
  --dump-capacity-warm-start /tmp/days-capacity-warm-start.txt

cargo run --release --features metal-spike --bin t20f_frontier -- \
  configs/benchmarks/tcp/fattree_k4_tcp_cubic_f16_smoke.toml \
  --engine device \
  --capacity-warm-start /tmp/days-capacity-warm-start.txt
```

The snapshot changes initial arena sizing only. Capacity is refuse-or-run, so a
successful retry or warm start cannot change simulation semantics.
