title: Testing

---

Days uses a mix of unit tests and integration tests under `tests/`.

## Run tests

Recommended:

```bash
cargo test -p days-executor -- --show-output
cargo test -p days --features test -- --show-output
cargo test -p days-legacy --features test -- --show-output
cargo test -p days-validation --features test -- --show-output
```

If you have `cargo-nextest` installed:

```bash
cargo nextest run --workspace --all-features --no-capture
```

The T13f full-load width lane deliberately uses the debug test profile and runs
one fixture per nextest process:

```bash
cargo xtask t13f-full-load
```

## Feature-gated test suites

Many tests use `#![cfg(feature = "test")]` to enable additional invariants and helpers (for example, verifying that local time tracking matches the simulation engine clock).

Some legacy tests also require protocol features:

- PFC tests: `cargo test -p days-legacy --features test,l2_pfc`
- DCQCN tests: `cargo test -p days-legacy --features test,dcqcn`
- Current Metal tests: `cargo test -p days-executor --features metal-spike`, `cargo test -p days --features test,metal-spike`, and `cargo test -p days-validation --features test,metal-spike`

## Test fixtures

Integration tests may have adjacent TOML fixtures (for example `tests/build_graph.rs` + `tests/build_graph.toml`). Configuration examples for manual runs live under `configs/`.
