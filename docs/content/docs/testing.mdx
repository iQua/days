**Scope: Days AGO**, plus the legacy and cross-engine packages in the default matrix. Tests live under `executor/tests/`, `tests/`, `legacy/tests/`, and `validation/tests/`.

## Default workspace matrix

```bash
cargo test -p days-executor -- --show-output
cargo test -p days --features test -- --show-output
cargo test -p days-legacy --features test -- --show-output
cargo test -p days-validation --features test -- --show-output
```

If `cargo-nextest` is installed, the same package surface can be selected with `cargo nextest run`. Do not use `--all-features` on a machine that cannot build both device toolchains.

`cargo xtask audit` runs two structural checks: only `days-validation` may depend on `days-legacy`, as a test-only dev-dependency; and every backend feature gate in `executor/src` must match a registered predicate and occurrence count.

## Planner equality

The planner equality test compares the device planners' precomputed plans with the retained earlier planner. It builds plans on the host and needs `test` plus one device feature:

```bash
# Apple Metal
cargo test -p days --features test,metal \
  --test planner_bit_equal -- --show-output

# CUDA (the build needs a CUDA 13 nvcc)
cargo test -p days --features test,cuda \
  --test planner_bit_equal -- --show-output
```

On a host without `nvcc`, the `cuda-planner-test` feature runs the same test for the CUDA planner. It enables `test`, and the executor's build script writes an empty placeholder instead of compiling CUDA kernels, so the test only builds plans on the host:

```bash
cargo test -p days --features cuda-planner-test --test planner_bit_equal
```

Adding `cuda-test-hooks` to that build compiles the kernels again, so it needs `nvcc`.

## TCP corpus byte identity

This ignored test lowers the committed TCP corpus and compares the CPU engine and each compiled device backend with the Scalar oracle:

```bash
cargo test --release -p days-validation --features test \
  --test tcp_corpora \
  full_tcp_corpora_are_byte_identical_across_available_backends \
  -- --ignored --exact --show-output
```

Add `metal` on Apple or `cuda` on a CUDA host to include that device, for example `--features test,metal`. The comparison removes device-omitted diagnostic planes, then requires the complete remaining `RunResult` to be byte-identical.

## E5 fixture gates

The fast check regenerates the E5 flow sets and compares them with the committed fixtures:

```bash
cargo test -p days --features test --test e5_wide_tcp_fixtures \
  e5_generator_reproduces_committed_flow_set_fixtures -- --exact --show-output
```

The same test target contains ignored full-run gates: Scalar count and trajectory gates, CPU completion anchors, and a protocol golden-vector gate. Building it with `--features test,metal-test-hooks` adds ignored Metal completion gates. List the exact names before selecting a long run:

```bash
cargo test -p days --features test --test e5_wide_tcp_fixtures -- --list
```

## Metal on Apple7-family GPUs

The Metal backend refuses Apple M1-family GPUs (Apple7); see [Installation](/docs/install#metal). To investigate the miscompilation, `DAYS_METAL_ALLOW_APPLE7=1` skips the refusal and prints a warning on standard error. Results on such a GPU are known to be wrong, and a cold build of the `days_round` pipeline takes about ten minutes.
