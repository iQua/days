Run commands from the repository root.

## Legacy config-driven run

```bash
RUST_LOG=info cargo run -p days-legacy --bin days -- configs/simple.toml
```

The legacy CLI accepts exactly one TOML path. With the default
`csv_logging = true`, it creates `log_path` (default `./output`) and initializes
`sources.csv`, `sinks.csv`, and `switches.csv`. Feature-gated report and
certificate files may also be created. Set this root key when filesystem output
is unwanted:

```toml
csv_logging = false
```

That setting suppresses directory creation, CSV rows, traces, and
`traces.json`; it does not skip simulation accounting.

## Exact Scalar run

The root example compiles TOML to an exact `SimulationImage` and runs the
global Scalar oracle:

```bash
cargo run --example scalar_benchmark -- \
  configs/benchmarks/tcp/fattree_k4_tcp_cubic_f16_smoke.toml
```

## Exact safe-horizon CPU run

```bash
cargo run --example round_benchmark -- \
  configs/benchmarks/tcp/fattree_k4_tcp_cubic_f16_smoke.toml \
  --workers 2 --repetitions 1
```

The CPU executor owns each logical process (LP) on one worker for a run. Each
round drains active LPs below an exclusive safe horizon, exchanges remote
events at a barrier, and canonically merges those events for the next round.

## Device smoke run

On Apple Metal:

```bash
cargo run --features metal-spike --bin t20f_frontier -- \
  configs/benchmarks/tcp/fattree_k4_tcp_cubic_f16_smoke.toml \
  --engine device
```

On a CUDA host, replace `--features metal-spike` with `--features cuda`.
The production runner prints a complete-state byte length and FNV-1a
fingerprint. It also supports capacity retry and warm-start flags; see
[`t20f_frontier`](/docs/reference/cli/t20f-frontier).

Metal/CUDA reject images containing RED, PFC, DCQCN/CNP state, or collective
generators. The error names the backend and recommends Scalar or CPU. This is a
capability rejection, not a silent fallback.
