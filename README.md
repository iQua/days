# Days: A Performant Discrete-Event Simulator for Network Simulations

Days is a discrete-event network simulator written in Rust. It models network components as actors (async coroutines) that communicate via message passing, with pluggable schedulers, flow models (packet distributions, TCP, optional DCQCN), and optional link-layer PFC support.

## Quick start

```bash
cargo run --release --bin days -- configs/simple.toml
```

Simulation outputs are written under `log_path` (default: `./output/`) as CSV files.

## Documentation

All design and configuration documentation lives under `docs/`:

```bash
cd docs/

```

Alternatively, one can directly visit the [documentation website](https://days.sh/docs/).

## Examples

- Config-driven runs: `cargo run --release --bin days -- configs/tcp_simple.toml`
- Rust examples: `cargo run --release --example basic`
- Inference workload generation:
  `cargo run --release --bin workload-generator -- DeepSeek-671B tests/fixtures/workload_generator/deepseek_default.toml --seq_length 16 --micro_batch 2 --world_size 32 --tensor_model_parallel_size 8 --expert_model_parallel_size 32 --pipeline_model_parallel 1 --phase decode --result_dir ./workload/collective/inference`
- Training workload generation:
  `cargo run --release --bin training-workload-generator -- --gpu_type A100 --model_name gpt_13B --world_size 128 --tensor_model_parallel_size 8 --pipeline_model_parallel 2 --expert_model_parallel_size 1 --global_batch 128 --micro_batch 1 --num_layers 40 --seq_length 1024 --hidden_size 2048 --vocab_size 32000 --enable_sequence_parallel --use_flash_attn --result_dir ./workload/collective/training`
- Training workload generation from TOML:
  `cargo run --release --bin training-workload-generator -- --config configs/workload/collective/training/llama_7b_8_a100.toml`
- Convert p2p flow dump to a days config:
  `cargo run --release --bin p2p-workload-import -- --input results/flow_dump/rank0_layer0_allreduce_ps0_bytes1048576_seq0.tsv --output configs/workload/p2p/training/p2p_case.toml`
- Run converted p2p config:
  `cargo run --release --bin days -- configs/workload/p2p/training/p2p_case.toml`
- Convert an FCT file to days inputs (TSV + TOML), then run:
  `cargo run --release --bin fct-to-days -- --workload-name llama_65b_512_h100 --class training --input-fct ../daytone-experiments/.astra-sim/simulation/llama_hpn7_fct.txt --run-days`

`FCT` means `Flow Completion Time`: each row describes one completed p2p flow
(`src`, `dst`, `bytes`, `start_time`, `fct`), and can be converted into a
days TOML workload config.

Workload files are organized under `workload/` (parallel to `results/`):

- `workload/collective/inference/`
- `workload/collective/training/`
- `workload/p2p/inference/`
- `workload/p2p/training/`

## Workload generator (inference)

`workload-generator` rewrites the legacy Python inference workload generation
logic in Rust for three model families:

- `DeepSeek-*`
- `Qwen3-Moe-*`
- `Qwen3-Next-*`

Current boundary:

- Matches legacy output format for `--aiob_enable=false` (default).
- Produces `.txt` workload files with the same header/row schema.
- Keeps legacy CLI-style underscore arguments (for example `--seq_length`).
- Supports `--aiob_enable` by loading an AIOB profile from `--aiob_profile`
  or the default path `results/aiob_outputs/<auto-generated-name>.txt`.

`AIOB` profile resolution:

- `--aiob_profile <path>`: always used when provided.
- `--aiob_enable` + missing profile: fails fast with a clear error.
- no `--aiob_enable` + missing profile: falls back to fixed compute time (`1`).
- Optional bootstrap: add `--auto_aiob_profile` to invoke the legacy Python
  profiler when the profile is missing. You can override Python and AICB path
  via `--python_bin` and `--aicb_dir` (or `DAYTONE_AICB_DIR`).
  By default, CLI first uses vendored `days/vendor/aicb`, then falls back to
  sibling `daytone-experiments/aicb`.
  This path requires a working Python AIOB environment (Torch/CUDA and legacy deps).

Current limitation:

- Rust generator does not natively implement GPU profiling; `--auto_aiob_profile`
  delegates profiling to the legacy Python AIOB path.

## Workload generator (training)

`training-workload-generator` rewrites the legacy Python training workload path
with characterization-locked parity for covered paths:

- Supports `--config <toml>` for parameterized generation; CLI args override
  values loaded from the config file.

- Megatron dense path (`moe_enable=false`) with both
  `enable_sequence_parallel=true` and `false`.
- Megatron MoE path (`moe_enable=true`, sequence parallel enabled).
- DeepSeek path (`--frame DeepSeek`, `moe_enable=true`) for sequence parallel mode.
- Supports `aiob_enable=true` when an AIOB profile is provided (`--aiob_profile`)
  or available at default path `results/aiob_outputs/<auto-generated-name>.txt`.
- Optional bootstrap: add `--auto_aiob_profile` to invoke the legacy Python
  profiler when the profile is missing. You can override Python and AICB path
  via `--python_bin` and `--aicb_dir` (or `DAYTONE_AICB_DIR`).
  By default, CLI first uses vendored `days/vendor/aicb`, then falls back to
  sibling `daytone-experiments/aicb`.
  This path requires a working Python AIOB environment (Torch/CUDA and legacy deps).

Legacy behavior note:

- Upstream Python `DeepSeek + aiob_enable=false` path crashes due a legacy
  `compute_cache=None` bug. Rust keeps deterministic generation for this path,
  while characterization parity is locked on the runnable Python path
  (`DeepSeek + aiob_enable=true`).

## End-to-end evaluation (days-local)

`days` now includes a local evaluation entrypoint:

```bash
cargo run --release --bin run-days
# or wrapper script
./scripts/run_days.sh
```

This script now runs **native days TOML configs directly**:

- scenarios:
  - `configs/workload/collective/training/*.toml`
  - `configs/workload/collective/inference/*.toml`
- runtime: `target/release/days` by default (built automatically)

Each scenario file under `configs/workload/collective/{training,inference}` is a runnable days config.
`run_days.sh` executes each config and writes:

- profile logs + memory logs under `results/evaluation/`
- per-run simulation logs under `results/evaluation/<run_name>.logs/`
- summary CSV under `results/evaluation/profile_days_*.csv`

Optional runtime override:

- set `DAYS_NATIVE_BIN=/path/to/days` to use a prebuilt binary
- set `DAYS_BUILD_PROFILE=debug` to build/run debug instead of release

Regression check:

```bash
./scripts/check_e2e_regression.sh
```

This runs native evaluation scenarios and validates expected output artifacts
under `results/evaluation/regression_<timestamp>/summary.csv`.

## Feature flags

- `l2` / `l2_pfc`: optional L2/PFC pipeline
- `dcqcn`: DCQCN flow type and models

- `test`: extra assertions and test helpers
